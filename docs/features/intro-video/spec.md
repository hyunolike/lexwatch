# 소개 영상 (intro-video)

- 상태: 구현 (2026-11-24)
- 관련: [first-visit-guide](../first-visit-guide/spec.md), 장면 계획 [storyboard.md](storyboard.md)

## 문제

README를 먼저 여는 채용 담당자는 데모 링크를 누르기 전에 무엇을 하는 제품인지 알아야 한다. 무료 서버라 첫 접속에 1분쯤 기다려야 해서, 기다리지 않고 핵심 흐름을 볼 방법이 필요했다.

## 요구사항

| ID | 내용 | 확인 |
|---|---|---|
| IV-01 | 실제 화면으로 핵심 흐름을 보여 준다 | 적발 표시, 승인 직전 경고, 수정 후 재검사 통과, 알림함, 관리자 작업 기록이 모두 로컬 스택의 실제 화면 캡처다. 재현 예시 라벨을 지우지 않는다 |
| IV-02 | 소리 없이 이해된다 | 장면마다 한국어 자막을 화면에 굽는다. 자막은 0.3초/단어 이상 머문다 |
| IV-03 | README 맨 위에서 바로 재생된다 | 배너 아래에 GitHub 재생기가 뜨고, 썸네일에 제목과 적발 화면이 보인다 |
| IV-04 | 첫 화면을 밀어내지 않는다 | 승인 대기함에 영상을 직접 넣지 않고, 처음 방문 안내 아래 줄에 링크만 둔다. 새 탭에서 열리고 화면 읽기 프로그램에도 알린다 |

## 결정

- **README 재생 방식.** GitHub README는 저장소 안 mp4를 재생기로 보여 주지 않는다. PR #23 댓글 입력창에 영상을 첨부해 `user-attachments` 주소를 받고(댓글은 등록하지 않음), README에 그 주소만 한 줄로 두어 재생기가 바로 뜨게 했다. 아래 줄에 Netlify의 `/intro.mp4` 링크를 예비로 둔다. 영상을 바꾸면 다시 첨부해 주소를 갈아 끼워야 한다.
- **썸네일.** GitHub 재생기는 첫 프레임을 썸네일로 쓴다. 제목과 적발 화면을 담은 썸네일(`tools/thumb.html`)을 만들어 첫 프레임에 넣고, `docs/images/intro-poster.jpg`로도 둔다.
- **파일 위치.** `web/public/intro.mp4`(약 4MB). 웹과 README가 같은 파일을 쓴다.
- **톤.** 출시 홍보 영상처럼 꾸미지 않았다. 남색 바탕에 실제 화면을 띄우고 커서, 확대, 강조 상자만 얹었다. 음악은 낮은 패드와 클릭음 정도다.
- **첫 화면.** 처음 방문 안내([first-visit-guide](../first-visit-guide/spec.md))가 같은 역할을 하므로, 기다리는 동안 볼 수 있는 링크 하나만 더했다.

## 다시 만들기

`tools/`의 스크립트로 다시 만든다. 작업 폴더(`brag-output/work/`, git 제외)에 `playwright`를 설치하고 Pretendard 가변 글꼴과 `lex-master.webp`를 복사해 둔다.

1. `docker compose up --build`로 로컬 스택을 띄운다. 다른 프로그램이 `localhost:3000`을 IPv6로 쓰고 있을 수 있어서, 캡처 스크립트는 Chromium에 `--host-resolver-rules=MAP localhost 127.0.0.1`을 준다.
2. `reset.sh`로 데모 데이터를 되돌린 뒤 `capture.js`, `capture-run.js`를 돌린다. 승인 단계가 데이터를 바꾸므로 다시 캡처할 때마다 먼저 되돌린다.
3. `audio.py`로 `music.wav`를 만들고, `render.js full`로 `comp.html`을 프레임마다 그려 `video-noaudio.mp4`를 만든다. `render.js stills 9,12,...`로 원하는 시각의 정지 화면만 볼 수 있다.
4. `thumb.js`로 썸네일을 그리고, ffmpeg로 소리를 합치고(loudnorm −20 LUFS) 썸네일을 첫 프레임에 넣는다.
5. 새 영상을 GitHub 댓글 입력창에 첨부해 받은 주소로 README의 영상 줄을 바꾼다.

## 검증 (2026-11-24)

- 길이 36.5초, 1920×1080, 30fps, 약 4.1MB, 통합 음량 −20.1 LUFS
- 장면마다 정지 화면과 전환 중간 프레임을 뽑아 확인했다. 겹침 없이 읽히고, 강조 상자가 "100분의 70", "100분의 50", 경고 대화상자, 재검사 결과, 알림 카드에 맞는다
- 화면 사이 전환은 이전 화면이 사라진 뒤 다음 화면이 나타나게 해 두 화면이 겹쳐 보이지 않는다. 같은 화면 위에 대화상자가 뜨는 경우만 교차한다
