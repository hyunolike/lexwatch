# 명세: 검토 보조를 눈에 띄고 바로 쓸 수 있게

- 상태: 구현 (2026-11-25)
- 작성: hh.jang
- 근거: 운영 화면 캡처(2026-11-25). 검토 보조가 페이지 맨 아래의 흰 카드라 다른 카드와 구분되지 않고, 빈 입력창 말고는 무엇을 물을지 실마리가 없으며, 기다리는 동안 회색 글 한 줄만 보였다. 같은 날 응답 실패는 [eval-fixes EF-12](../eval-fixes/spec.md)에서 고쳤다.
- 관련: [ai-governance](../ai-governance/spec.md)(민감정보 가리기, 근거 안에서만 답), [design-system-v2](../design-system-v2/spec.md)(출처 색, 인용 칩, 분할 화면)

작성자가 고른 범위는 제안 1, 2, 4다. 진짜 스트리밍(3)과 어디서든 열기(5)는 다음 범위다.

## 요구사항

| ID | 요구 | 판단 기준 |
|---|---|---|
| RC-01 | AI 영역임을 출처 색으로 보인다 | 카드 왼쪽에 AI 출처 색(`prov-ai`) 띠, 머리에 AI 아이콘과 "근거 N건 안에서만 답해요". 색만으로 구분하지 않도록 글을 함께 둔다. 상태 색 계열은 쓰지 않는다(DS2-05) |
| RC-02 | 추천 질문으로 바로 시작한다 | 대화가 비어 있을 때 이 초안에서 만든 질문 최대 3개를 칩으로 보인다. 확인 필요 문장이 있으면 그 수, 신구조문이 있으면 첫 조문 번호를 넣는다. 누르면 바로 보낸다. 모델을 부르지 않는 순수 함수(`suggestQuestions`)로 만든다 |
| RC-03 | 기다리는 동안 움직임과 단계를 보인다 | 답을 기다리는 동안 점 세 개가 움직이고 "근거 N건을 읽고 답을 쓰는 중"을 보인다. 움직임 줄이기 설정에서는 움직이지 않는다. 새 답은 짧게 나타난다(motion-safe) |
| RC-05 | (2026-11-25 추가) 초안에 관한 질문에 답한다 | 채팅 요청에 검토 중인 초안 문장, 인용, 자동 검사 결과(최대 40문장, 문장당 10건)를 함께 보낸다. 초안 문장은 질문처럼 고객사 이름을 가린다. 프롬프트는 초안을 "근거가 아님"으로 표시하고, 문장이 맞는지는 근거와 대조해 근거 ID를 인용하게 한다. 초안이 없으면 그렇다고 밝힌다. 배포 뒤 "영향 검토 초안 문제점 요약해줘"가 가드레일은 통과했지만 모델이 초안을 받지 못해 거절한 데서 나왔다 |
| RC-06 | (2026-11-25 추가) 근거가 많아도 마감 안에 답한다 | 운영 검토(근거 54건)에서 모든 본문(각 최대 2,000자)을 넣자 모델이 30초 마감을 넘겨 거절했다(로컬 재현 3회 중 2회). 근거 본문은 초안이 인용한 것, 신구조문, 나머지 순으로 합계 4,500자(건당 800자)까지 넣고, 넘치는 근거는 ID만 나열한다(도구로 본문 확인). 처음 10,000자로 고쳤지만 대체 공급자 Groq 무료 등급이 프롬프트 토큰을 분당 8,000으로 세어 다시 줄였다. AI 마감은 36초(API 시도당 40초보다 짧게). 거절 이유를 질문 없이 로그에 남긴다 |
| RC-07 | (2026-11-25 추가) Cloudflare 한도가 끝나도 Groq로 답한다 | Groq는 JSON 형식 지정과 도구를 한 요청에 받지 않아(400) 검토 보조의 대체 경로가 늘 실패했다. 검토 보조는 도구를 `OptionalTools`로 표시하고, Groq는 이 표시가 있으면 도구를 빼고 형식을 지킨다. 분석 단계의 필수 도구는 바꾸지 않는다 |
| RC-04 | 답의 인용을 근거와 잇는다 | 답 아래 인용을 인용 칩(`CitationChip`)으로 보인다. 1280px 이상 분할 화면에서는 누르면 오른쪽 근거 패널이 그 근거로 바뀌고 패널로 스크롤한다. 그 밖에서는 칩이 미리보기 팝오버를 연다 |
