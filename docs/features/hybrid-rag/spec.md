# 명세: 조문 하이브리드 검색 (2026-11-20)

- 작성: hh.jang
- 관련: [Cloudflare 공급자 명세](../cloudflare-ai/spec.md), [설계](design.md), [작업](tasks.md), [검토 기록](reviews/)

## 해결할 문제

1. **실행의 조문 집합을 의미로 찾는 수단이 없다.** 분석 에이전트의 도구 다섯 개 가운데 조문을 가져오는 것은 번호로 묻는 `get_article`과 `compare_old_new`뿐이다. 135조짜리 법령에서 실무그룹과 관련된 조문을 찾으려면 번호를 추측해야 한다.
2. **분석 입력이 너무 크다.** 백엔드가 실행의 근거 전체를 분석 프롬프트에 넣는다(공개 데모의 고등교육법 시행령은 135건, 각 4,000자까지). 2026-11-20 공개 데모에서 분석이 120초 제한을 다 쓰고 근거 부족으로 끝났다.
3. **임베딩이 꺼져 있다.** NVIDIA 키가 없어 공개 데모의 임베딩은 256차원 해시 대체 구현이다. 채용 공고 우대 요건인 RAG를 데모가 보여 주지 못한다.

## 범위

- 포함: 조문 청킹과 색인, PostgreSQL 한 쿼리 안의 BM25와 벡터 결합 검색, 분석 입력을 검색 결과로 줄이기, 색인과 검색에 Cloudflare `bge-m3` 임베딩, 재현 가능한 검색 평가
- 제외: 판례와 행정규칙 색인, 여러 실행에 걸친 공용 색인, 에이전트가 직접 부르는 검색 도구, 재순위 모델, 분류의 그룹 유사도 모델 교체(지금 흐름 유지, 7절 참고)

## 요구사항

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| RAG-01 | 조문 구조 단위로 나눈다 | `kind = "law"` 근거 하나가 청크 하나. 본문이 1,200자를 넘으면 항(원문자 ①~⑳로 시작하는 줄) 경계에서 1,200자 안으로 묶어 나눈다. 청크 ID는 `{근거 ID}#{n}`(n은 1부터)이고 원래 근거로 되돌아간다(DB 외래 키로 보장) |
| RAG-02 | 관련 있는 실행만 색인한다 | `classify`가 진행할 그룹이 있을 때만 `index_articles`를 낸다. 같은 실행을 다시 돌려도 청크가 중복되지 않는다. 임베딩을 받지 못하면 키워드 색인만 만들고 단계 출력에 `dense: "unavailable"`과 이유를 남긴다 |
| RAG-03 | 하이브리드 검색 | 한 실행 안에서 BM25(k1=1.4, b=0.75) 상위 50과 벡터 코사인 상위 50을 RRF(k=60)로 합친다. 한 SQL 쿼리로 실행하고 결과마다 두 경로의 순위를 낸다. 같은 입력에는 같은 순서를 낸다 |
| RAG-04 | 분석 입력을 줄인다 | 분석 요청의 근거는 변경 조문(신구조문, 조문 번호순 최대 12건)과 검색 상위 8건(변경 조문과 같은 조문은 제외하고 채움)이다. 검색 질의는 실무그룹 관심 분야와 변경 조문의 제목, 새로 바뀐 구간으로 만든다 |
| RAG-05 | 출처를 숨기지 않는다 | `index_articles`의 출처 라벨은 임베딩 공급자(Cloudflare 또는 대체 구현)다. 색인과 질의의 임베딩 모델이 다르면 벡터 경로를 쓰지 않는다 |
| RAG-06 | 검색 품질을 숫자로 보인다 | 실제 녹화 법령 3개(근로기준법, 개인정보 보호법, 전자금융거래법)에 대한 질의 30건 이상과 정답 조문. 질의 유형은 조문 표현(keyword), 실무자 표현(paraphrase), 운영형(관심 분야 + 변경 내용). BM25, 벡터, 하이브리드의 recall@5, recall@10, MRR과 질의별 승패를 `eval/results/`에 저장한다. 임베딩은 한 번 계산해 저장소에 두어 다시 돌릴 때 무료 한도를 쓰지 않는다 |
| RAG-07 | 검색이 무엇을 찾았는지 보인다 | `index_articles`와 `analyze` 출력에 청크 수, 임베딩 상태, 보낸 근거 수(변경/검색), 검색 상위 조문을 남긴다. 실행 타임라인의 300자 요약 안에 들어간다 |

## 오류 상황

| 상황 | 동작 |
|---|---|
| 색인 때 임베딩 실패(한도 초과, 키 없음, 차원 불일치) | 키워드 색인만. `dense: "unavailable"`, 이유 기록. 단계는 성공 |
| 질의 임베딩 실패 또는 모델 불일치 | 키워드 경로만. 단계는 성공 |
| 실행에 색인이 없다(기능 배포 전 실행) | 지금처럼 근거 전체를 보내고 `retrieval: "no_index"`를 남긴다 |
| 검색 0건 | 변경 조문만 보낸다 |
| 변경 조문 0건 | 검색 상위만 보낸다 |
| 둘 다 0건 | 지금처럼 근거 전체를 보내고 `retrieval: "fallback_all"`을 남긴다 |
| 변경 조문이 12건 초과 | 조문 번호순 앞 12건. `oldnewTruncated: true` |

## 성공 판단

- 하이브리드의 recall@10이 BM25보다 높고, 이긴 질의 수가 진 질의 수보다 많다. 아니면 그대로 보고하고 운영 기본값(`Retrieval:Mode`)을 BM25로 둔다.
- 분석 시간과 프롬프트 토큰을 같은 법령으로 변경 전후 3회 이상 비교해 기록한다.
- 근거 전체로 만든 기존 초안이 인용한 `law` 근거 가운데 새 입력에 들어가는 비율(인용 재현율)을 재현 기록으로 계산해 기록한다.
