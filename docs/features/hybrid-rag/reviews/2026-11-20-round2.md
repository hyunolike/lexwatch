# EGM 2차 검토 (2026-11-20)

구현 준비도 검토자가 새 문맥에서 수정본과 1차 조치를 대조했다. 1차 블로커는 모두 해소(분석 질의는 부분 해소), 새 블로커 없음, 주요 3건, 경미 5건.

## BM25 SQL 검증

idf, tf, 문서 길이, avgdl 모두 `lexical.py`와 같다. 동점 정렬은 Python에 청크를 `Ord` 순서로 넘길 때만 같고, 점수 0인 문서는 SQL이 내지 않으므로 동등성 비교는 점수 > 0인 문서로 한정한다.

## 조치

| 지적 | 조치 |
|---|---|
| 마지막 조인 `c."ChunkId" = "ChunkId"`가 모호(42702) | `FULL JOIN ... ON` + `coalesce(bm."ChunkId", dense."ChunkId")`(design 4) |
| 질의 64토큰 상한이 새 구간을 잘라 냄, 제목에 법령명·"신구조문 대비" 잡음 | 출처별 할당(새 구간 48, 조문 제목 16, 관심 분야 32), 괄호 안 제목만(design 5.3) |
| 변경 구간 오프셋의 기준 문자열 미정 | `[신조문]\n` 뒤 부분 문자열에 적용(design 5.3) |
| `topEvidence` 값, 벡터 없는 Dense 모드 | 8 + 변경 조문 수, 쿼리 생략과 0건(design 4) |
| 출력 형식 충돌, 한글 이스케이프로 300자 초과 | `retrieval.status` 객체로 통일, 조문 번호만, 이유는 영문 코드(design 5.2, 5.3) |
| SqlQueryRaw 열 이름·타입 | 별칭을 속성 이름에 맞추고 캐스트(design 4) |
| 동등성 테스트의 근접 동점 | 점수를 허용 오차(1e-9)로 비교하고, 허용 오차 안의 동점은 순서를 따지지 않는다(tasks 6) |
| `index_articles` 예외 시 실행 실패 | 의도로 남김: 임베딩 실패는 저하로 처리하므로 예외는 진짜 장애뿐(design 9) |
| `/embed` 대체 래퍼 위치와 응답 provider | 구현 작업 12에서 정한다: `get_retriever()`가 돌려주는 래퍼가 실패 시 lexical로 바꾸고 응답 provider를 lexical 것으로 단다. 타임아웃도 대체 조건 |

검토 반복은 두 번으로 마친다. 남은 쟁점은 1차 기록과 같다.
