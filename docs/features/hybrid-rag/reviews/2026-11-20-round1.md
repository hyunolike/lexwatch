# EGM 1차 검토 (2026-11-20)

검토자 세 명(설계, 구현 준비도, 코드 대조)이 새 문맥에서 spec.md와 design.md 초안을 검토했다. 블로커 7건(중복 제거), 주요 20건 안팎.

## 조치

| 지적 | 조치 |
|---|---|
| 근거 ID 형식이 실제(`law:001872:제56조`)와 다름 | 예시와 청크 ID 규칙 수정(design 3.1) |
| 분석 질의의 "개정 요약" 미정의, 질의가 변경 조문과 겹침, 평가 질의와 분포 다름 | 질의 = 관심 분야 + 변경 조문 제목 + 새 구간, 토큰 64개 상한. 변경 조문과 같은 조문은 검색에서 제외. 평가에 운영형 질의 유형 추가(design 5.3, 8) |
| 핸들러가 트랜잭션 밖에서 실행되어 원시 SQL 삭제가 즉시 커밋됨, tsvector 쓰기 방법 없음 | EF 추적 엔터티로만 저장, 키 기준 갱신·추가·남은 것 삭제. tsvector를 쓰지 않고 토큰 배열 `text[]` + SQL BM25로 변경(design 3.1, 4, 5.2) |
| 분류가 임베딩 실패로 실행 전체를 실패시킴 | AI 서비스가 Cloudflare 실패 시 lexical로 대체하고 kind=fallback. 분류 흐름 유지(design 6, 7) |
| 색인 없는 실행의 분석 동작 미정 | 근거 전체 + `retrieval: "no_index"`. 둘 다 0건이면 `fallback_all`(spec 오류 상황, design 5.3) |
| 재순위 평가 모드를 구현할 경로 없음 | 재순위를 범위에서 제외(spec 범위) |
| `ts_rank_cd`에 IDF가 없어 기준선이 약함 | SQL로 BM25 직접 계산, `lexical.py`와 동등성 테스트(design 1, 4, 8) |
| 색인을 분류 앞에 두면 관련 없는 실행까지 색인(용량, Neurons) | 순서를 classify → index_articles → analyze로 변경(design 1, 5.1) |
| 질의 벡터 차원·모델 불일치 시 pgvector 오류 | 길이, 모델이 맞을 때만 dense CTE 포함, `EmbedModel` 조건(design 4, 5.3) |
| 일부 배치 실패, 리스 5분 초과 위험 | 전부 아니면 전무, 임베딩 예산 90초(design 5.2) |
| `LIMIT @k` 청크 단위, 동점 비결정 | 100행 받아 C#에서 근거별 합침, 정렬에 Ord와 ChunkId(design 4) |
| null 벡터 매개변수 타입 오류 | 모드별 쿼리 조합, `vector` 타입 명시(design 4) |
| 평가 CI 제외 장치 없음 | `--filter "Category!=eval"` 두 곳(design 8) |
| 캐시 키에 모델과 입력 유형 없음, 생성기 미정 | 키 = sha256(model, input_type, text), `scripts/embed_cache.py`, 누락 시 실패(design 8) |
| 타임라인 300자 절단, 단계 라벨 없음 | 출력 요약을 300자 안으로, labels.ts·RetryPolicy·Program 등록 명시(design 5.2, 5.3) |
| `AiMapping.Evidence`가 순서를 다시 섞음, 조문 번호 문자열 정렬 | 순서 유지 매핑, 자연 정렬 함수(design 3.2, 5.3) |
| 명세의 "도구는 get_article뿐"이 틀림 | 문제 1 문장 수정 |
| "135 → 20건 이하"는 설계상 당연히 참 | 성공 판단을 시간·토큰 전후 비교와 인용 재현율로 교체 |
| 그룹 임베딩 열 1024 마이그레이션 위험 | 이번 범위에서 빼고 지금 흐름 유지(design 7) |
