# 명세: 아침 수집의 AI 깨우기와 실패 알림 (2026-11-23)

- 작성: hh.jang
- 관련: [배포 런북](../../deploy.md), [`.github/workflows/collect.yml`](../../../.github/workflows/collect.yml)

## 해결할 문제

2026-11-23 아침 수집이 3건(도시개발법 시행규칙, 등기사항증명서 등 수수료규칙, 수산생물질병 관리법 시행규칙)을 만들었다. 세 건 모두 분류 단계가 다섯 번 시도한 끝에 `AI_UPSTREAM_ERROR (502)`로 실패했다. 그런데 `collect` 잡은 성공으로 끝나서 관리자가 실행 이력을 열기 전까지 아무도 몰랐다.

- 잡은 API만 깨우고 AI 서비스(Render free, 별도 인스턴스)는 깨우지 않는다. AI 서비스는 잠든 채로 첫 분류 요청을 받는다.
- 분류 재시도 대기는 2, 4, 8, 16초로 합쳐서 약 30초다. Render 무료 인스턴스가 깨어나는 시간(오늘 `/health` 17.5초, 보통 1분 안팎)과 겹치면 다섯 번 모두 502를 받는다.
- 잡은 `{"created":3}`만 보고 끝나서 실행 결과를 확인하지 않는다.

## 요구사항

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| CH-01 | AI 서비스를 깨우는 짧은 호출 | `POST /jobs/wake-ai`(작업 토큰, 없거나 틀리면 401)가 AI `/health`를 한 번 부른다. 시도당 10초 제한. 응답하면 200 `{ ai: "ok", ms }`, 실패하거나 시간 안에 응답이 없으면 503 `{ code: "AI_ASLEEP" }`. `AiGateway`를 거치지 않고 `IAiClient.HealthAsync`를 직접 부른다 |
| CH-02 | 수집 전에 깨운다 | `collect` 잡이 수집 호출 전에 `wake-ai`를 15초 간격으로 최대 12번(약 3분) 부른다. 끝내 503이어도 그 단계는 실패시키지 않고 수집을 진행한다(법령 수집은 AI가 필요 없고, 실패는 CH-04가 알린다) |
| CH-03 | 수집이 만든 실행 ID를 돌려준다 | `POST /jobs/collect` 응답에 `runIds: [..]`를 더한다(`created`, `skipped`는 그대로) |
| CH-04 | 이번 수집의 실패를 잡 실패로 올린다 | 잡이 `runIds` 각각을 `GET /api/runs/{id}`(헤더 `X-Demo-Role: admin`)로 1분마다 조회한다. 남은 일(실행 상태 `Queued`·`Running`, 상태가 `Pending`·`Running`·`RetryScheduled`인 단계, `Analyzing` 그룹, 조회 실패)이 없어지면 멈춘다. 분류가 끝나면 실행 상태는 곧바로 `InReview`가 되고(`ClassifyStep`) 그룹 분석과 크리틱은 그 뒤에 돌기 때문에 실행 상태만으로는 판단하지 않는다. 실행이 `Failed`이거나, (단계, 그룹)마다 마지막 시도가 `Failed`인 단계가 있으면(그룹 분석 실패 포함) 법령명과 실패 단계를 출력하고 잡을 실패로 끝낸다. 15분이 지나도 남은 일이 있으면 그것도 실패로 끝낸다. 조회하는 동안 `wake-ai`도 불러 API와 AI가 깨어 있게 한다 |
| CH-05 | 잡 시간 상한 | 깨우기 3분 + API 깨우기 3분 + 수집(재시도 포함) 최대 약 6분 + 감시 15분을 넘지 않도록 `timeout-minutes: 30`. 2026-11-26 감시 25분, 상한 40분으로 늘림([ai-wake-retry](../ai-wake-retry/spec.md) WR-05) |

## 운영 기록

- 2026-11-23 머지 직후 수동 실행(첫 판): 5건을 만들고 2분 만에 "진행 중 0건"으로 끝났다. 그 시점에 두 실행은 실행 상태만 `InReview`이고 그룹은 `Analyzing`, 크리틱 1단은 시도 0회 `Pending`이었다. 잡이 핑을 멈추자 API가 잠들어 처리가 멈췄다. CH-04를 실행 상태에서 남은 단계와 그룹 상태로 넓혔다.
- 2026-11-23 #20 머지 뒤 수동 실행(둘째 판, run 45155128769): 새 법령이 없어 `created 0, skipped 8`, 감시는 "새 실행이 없다"로 바로 통과했다. 감시 본문은 같은 날 첫 판이 만든 5건에 로컬에서 그대로 돌려 확인했다. 첫 바퀴에 남은 일 0건, 실패 단계 없음, 종료 코드 0이었다. 처리 중인 실행을 기다리는 경로는 다음 예약 실행에서 새 법령이 들어올 때 확인한다.

## 범위 밖

- 재시도 정책(`RetryPolicy`) 변경. 깨우기를 먼저 하므로 지금 간격을 유지한다. → 2026-11-25 수집에서 깨우기 3분으로도 AI가 깨지 않아 [ai-wake-retry](../ai-wake-retry/spec.md)에서 바꿨다(깨는 중 오류만 약 10분 대기, 감시 25분).
- 재현 실행. 수집이 만든 ID만 보므로 섞이지 않는다.
- 실패한 실행의 자동 재실행. 실패 원인을 사람이 확인한 뒤 관리자 화면에서 다시 실행한다.
- README의 "매일 07:00" 문구와 GitHub cron 지연(실제 10:50~12:00 KST) 문제. 별도로 다룬다.
