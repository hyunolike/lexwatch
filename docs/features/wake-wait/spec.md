# 서버 깨우는 동안의 대기 화면 (wake-wait)

- 상태: 검토 반영본 v2 (2026-11-24). 변경: 단계를 둘로 줄임, 경과 시간 기준, 60초 뒤 안내와 줄무늬, `/health` 핑 규칙, 잠꼬대와 카드 문구
- 근거: [research.md](research.md)
- 관련: `WakeGate.tsx`(design-system 명세의 "서버 깨우기"), [first-visit-guide](../first-visit-guide/spec.md), [intro-video](../intro-video/spec.md)

## 문제

API가 Render 무료 플랜이라 15분 동안 요청이 없으면 잠들고, 첫 요청이 20초에서 1분쯤 붙잡힌다. 지금 대기 화면은 정지 이미지와 "(0/24)"만 보여서, 첫 요청이 걸려 있는 동안 시도 횟수도 오르지 않는다. 처음 방문 안내 아래에 놓여 첫 화면 아래쪽에 반쯤만 보인다. 방문자는 화면이 멈췄다고 느낀다.

## 범위

- `WakeGate`의 대기 상태 화면. 승인 대기함, 초안 상세, 알림함, 실행 이력 목록과 상세가 모두 같은 부품을 쓴다.
- 실패와 포기 화면(다시 시도 버튼)은 그대로 둔다. 시도 횟수 규칙(5초 간격, 24회)도 그대로 둔다.
- 범위 밖: 서버를 미리 깨우는 장치(예약 핑), 실제 대기 시간 단축.

## 요구사항

| ID | 요구 | 확인 |
|---|---|---|
| WW-01 | 기다리는 동안 화면이 살아 있다 | 경과 시간("12초째", "1분 15초째")이 1초마다 오른다. 경과 시간은 데이터 요청을 시작한 때부터 세고 초 아래는 버린다. 마스코트가 천천히 숨쉬듯 움직인다(움직임 줄이기 설정이면 멈춘다) |
| WW-02 | 얼마나 걸리는지 안다 | 안내 문장 "보통 30초에서 1분 걸려요."와 양 끝에 "0초", "1분"이 적힌 시간 막대를 보인다. 막대는 일의 양이 아니라 경과 시간이다. 60초가 지나면 안내 문장을 "평소보다 오래 걸리고 있어요. 조금만 더 기다려 주세요."로 바꾸고, 막대는 채운 채 멈춰 두지 않고 흐르는 줄무늬로 바꾼다. 경과 시간은 계속 센다 |
| WW-03 | 무슨 일이 일어나는지 안다 | 두 단계를 체크리스트로 보인다. (1) 서버 깨우기: `/health`가 200으로 답하면 완료 (2) 〈불러올 것〉 불러오기: 데이터 응답이 오면 완료. 완료 표시는 실제 응답으로만 한다. 데이터가 오면 두 단계가 모두 완료된 모습을 0.6초 보인 뒤 본 화면으로 넘어간다(움직임 줄이기 설정이면 바로 넘어간다). 왜 기다리는지 한 문장으로 적는다: "이 데모는 무료 서버에서 돌아가서, 15분 동안 방문이 없으면 잠들어요."([Render 문서](https://render.com/docs/free)) |
| WW-04 | 기다림을 채울 거리가 있다 | (a) 렉스를 누르면 흔들리며 잠꼬대가 바뀌고 "렉스를 n번 흔들었어요"가 보인다. "눌러도 빨라지지는 않아요"를 함께 적고, 잠꼬대에는 진행이나 남은 시간처럼 읽히는 말을 넣지 않는다 (b) 이야기 카드 5장이 7초마다 넘어가고, 이전, 다음, 멈춤 버튼이 있다 (c) 36초 소개 영상 링크 |
| WW-05 | 첫 화면 위쪽에서 보인다 | 1280×800 화면에서 처음 방문 안내가 열려 있어도 대기 화면의 제목과 시간 막대가 첫 화면 안에 보인다. 폭 375px에서 가로 스크롤이 없다 |
| WW-06 | 접근성 | 대기 화면의 낭독 영역(`role="status"`)은 빈 자리 단계부터 미리 그려 둔다. 이 영역에는 제목, 안내 문장, 단계만 넣어 처음 나타날 때, 단계가 바뀔 때, 60초를 넘길 때만 읽힌다. 경과 시간, 막대, 잠꼬대, 카드는 그 밖에 둔다. 렉스 놀이는 이름이 있는 버튼이다. 이야기 카드는 자동으로 넘어가므로 멈춤 버튼이 있다(WCAG 2.2.2). 색만으로 단계 완료를 나타내지 않는다 |
| WW-07 | 문구는 사실만 쓴다 | 이야기 카드와 단계 이름은 README, 코드, 호스팅 문서로 확인되는 내용만 쓴다. 사내 용어(크리틱, 재현, 실무그룹, 실행)는 쓰지 않는다 |

## 오류 상황

- `/health` 핑은 대기 화면이 나타난 뒤(0.4초)에 시작하고 한 번에 하나만 보낸다. 502, 503, 504나 네트워크 오류면 3초 뒤 다시 보낸다. 그 밖의 응답(404, 500)이면 멈추고 1단계를 진행 중으로 둔다. 데이터가 오거나 포기, 실패 화면이 되거나 화면을 떠나면 요청을 취소하고 멈춘다.
- Render는 깰 때까지 요청을 붙잡아 두므로 `/health`와 데이터 응답은 거의 함께 온다. 대기 시간 대부분은 "서버 깨우기 진행 중"으로 보이는 것이 정상이다.
- 데이터 요청이 대기 응답으로 끝나면 지금처럼 5초 뒤 다시 시도한다. 경과 시간은 처음 요청 시각부터 이어서 센다.
- 서버가 이미 깨어 있으면 0.4초 안에 응답이 와서 대기 화면 없이 본 화면이 뜬다. 그 전에는 대기 화면 높이의 빈 자리만 둔다.
- 포기 화면에서 다시 시도를 누르면 경과 시간, 단계, 0.4초 지연을 처음부터 적용한다.
- 관리자 쿠키가 있으면 하이드레이션 직후 역할이 바뀌어 `WakeGate`가 다시 마운트되고 경과 시간이 0부터 다시 시작한다. 지금 동작과 같고 받아들인다.
