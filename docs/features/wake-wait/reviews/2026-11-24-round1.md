## 구현 준비도 (차단 2, 중대 6, 경미 10)

| # | 지적 | 심각도 | 조치 |
|---|---|---|---|
| 1 | `/health` 핑의 취소, 동시 요청 수, 멈춤 조건, 404/500 처리가 없음 | 차단 | 한 번에 하나, `AbortController`, 데이터와 포기와 실패에서 멈춤, 그 밖의 응답이면 멈추고 진행 중으로 둠(spec 오류 상황, design 4절) |
| 2 | 데이터가 오면 바로 본 화면이라 마지막 단계 완료가 보이지 않음. Render는 두 응답이 거의 함께 옴 | 차단 | 완료 모습을 0.6초 보인 뒤 넘김(움직임 줄이기면 바로). 두 응답이 거의 함께 오는 것을 정상으로 명세에 적음 |
| 3 | 경과 시간 시작점이 spec과 design에서 다름 | 중대 | 데이터 요청 시작 시각, 초 아래 버림으로 통일 |
| 4 | 렌더 중 `ref.current`와 `Date.now()`가 react-hooks 규칙에 걸림, 다시 시도 때 초기화 범위 없음 | 중대 | 시작 시각은 effect 안에서 잡아 타이머 콜백에서 state로, 1초 갱신은 `WakeWait`의 `now` state. `reload`가 모든 대기 상태를 되돌림 |
| 5 | `apiFetch`의 `X-Demo-Role` 헤더 때문에 매번 CORS 사전 요청 | 중대 | 헤더 없는 `pingHealth(signal)`을 `api.ts`에 추가 |
| 6 | 서버가 깨어 있어도 페이지마다 `/health`가 나감 | 중대 | 대기 화면이 뜬 뒤(0.4초)에만 핑 |
| 7 | 1280×800 첫 화면에 들어오는 근거 없음 | 중대 | design 6절에 높이 계산, 구현 뒤 Playwright로 측정 |
| 8 | 낭독 영역이 0.4초 뒤 새로 생기면 첫 내용이 안 읽힘, 느림 안내가 `aria-hidden` 안에 있음 | 중대 | 빈 자리 단계부터 낭독 영역을 그려 둠, 안내 문장을 낭독 영역으로 옮김 |
| 9~18 | 단계 조합 표, 빈 자리 높이, 숨쉬기와 흔들기 애니메이션 충돌, 카드 멈춤 합성 규칙, 막대 역할, `label` 필수 여부, 역할 쿠키 재마운트, 15분 근거, 느림 문구 위치, design-system 문서 갱신 | 경미 | 모두 design에 반영. 15분 근거는 Render 문서로 바꿈 |
