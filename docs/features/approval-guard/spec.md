# 명세: 승인 전 적발 확인과 비율 대조 (2026-11-23)

- 작성: hh.jang
- 관련: [설계](design.md), [작업](tasks.md), [전체 설계 문서](../../superpowers/specs/2026-11-16-lexwatch-design.md)

## 해결할 문제

2026-11-23 배포본(3eb80de)을 변호사 역할로 써 보다가 틀린 내용이 승인 한 번으로 알림함에 발송되는 경로 세 개를 찾았다.

1. **수정 후 승인은 크리틱을 다시 돌리지 않는다.** 재현 예시 근로기준법(크리틱 2단 적발, "100분의 70")에서 문장을 "100분의 80"으로 고치고 인용은 그대로 둔 채 수정 후 승인했다. 서버는 인용 ID가 근거 저장소에 있는지만 보고 통과시켰고, 알림함에 "통상임금의 100분의 80 이상으로 바뀐다"가 발송 완료로 남았다.
2. **적발이 남은 초안도 확인 없이 승인된다.** 승인 대화상자는 어느 그룹으로 발송되는지만 알린다. 목록에서 바로 들어와 승인하면 적발 사실을 보지 않고 지나칠 수 있다.
3. **크리틱 2단이 비율 표기를 대조하지 않는다.** 조문번호, 날짜, 금액(원), 기간(일·개월·년)만 본다. 가산율, 과징금 비율처럼 "100분의 50", "50%"로 쓰는 숫자는 틀려도 잡히지 않는다. 데모의 "100분의 70" 적발은 재현 fixture에 미리 적어 둔 값이라, 같은 초안을 실제 크리틱에 넣으면 적발이 0건이다.

## 범위

- 포함: 크리틱 2단 비율 대조, 승인 API의 적발 확인 규칙, 수정 문장 재검사, 웹 승인 흐름
- 제외: 크리틱 3단(과잉해석) 재실행. 모델 호출이라 승인 요청 안에서 기다리기 어렵다. 저장된 3단 적발을 AG-03 규칙으로 옮겨 쓴다.
- 제외: "개정되지 않은 조문을 개정 사항으로 서술"하는 과잉해석 규칙. 별도 작업으로 남긴다.

## 요구사항

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| AG-01 | 크리틱 2단이 비율을 대조한다 | 문장의 `A분의 B`(`100분의 50`, `1천분의 3`, `백분의 50`), `N%`, `N퍼센트`가 인용 근거 본문에 같은 값으로 없으면 `C2-MISMATCH`. 값은 소수 4자리로 반올림해 비교하므로 표기가 달라도 같은 값이면 통과한다(`100분의 50` = `50%` = `2분의 1`). `%p`(퍼센트포인트)는 비율로 보지 않는다. 기존 조문, 날짜, 금액, 기간 판정은 바뀌지 않는다 |
| AG-02 | 승인 때 1·2단을 다시 검사한다 | 승인 요청마다 승인할 초안(수정했으면 수정본, 아니면 최신 초안)에 크리틱 1단과 2단을 다시 실행한다. 저장된 1·2단 적발 대신 이 결과를 쓴다. 결정적 규칙이라 비용이 작고, 규칙이 바뀐 뒤 대기 중이던 초안에도 새 규칙이 적용된다 |
| AG-03 | 3단 적발은 문장 내용으로 옮긴다 | 수정본의 문장이 수정 전 어떤 문장과 문장, 인용이 모두 같으면 그 문장의 3단 적발을 새 위치로 옮긴다. 고친 문장의 3단 적발은 같은 위치에 문장이 남아 있으면 그 문장에 "(수정 전 문장)" 표시를 붙여 옮기고, 위치가 사라졌으면(문장 삭제) 버린다 |
| AG-04 | 적발이 있으면 확인한 수를 받아야 승인한다 | AG-02와 AG-03으로 모은 적발이 1건 이상이고 요청의 `acknowledgedFindingCount`가 그 수와 다르면(없음 포함) 422 `UNRESOLVED_FINDINGS`. 응답에 `findings: [{ sentenceIndex, tier, ruleId, message }]`(문장 순, 단 순)가 있다. 이때 상태, 초안, 승인 기록, 알림 큐는 바뀌지 않는다 |
| AG-05 | 확인하고 승인하면 기록이 남는다 | 수가 맞으면 승인되고 알림이 나간다. 승인 기록에 `AcknowledgedFindingCount`가 남는다(적발 0건이면 0). 수정본이면 모은 적발이 새 초안 버전의 적발로 저장된다 |
| AG-06 | 적발이 없으면 지금과 같다 | 적발 0건이면 `acknowledgedFindingCount` 없이 승인된다. 기존 400, 403, 404, 409 응답은 바뀌지 않는다 |
| AG-07 | 승인 화면이 적발을 확인받는다 | 승인(수정 없음)과 수정 후 승인 모두 먼저 확인 수 없이 보낸다. 다만 화면에 적발이 보이는 초안은 승인 대화상자에 "확인이 필요한 문장 N개"를 알리고 화면의 적발 수를 함께 보낸다. 422를 받으면 결정 영역 위에 문장별 적발 목록과 "적발 N건을 확인했고 그대로 승인" 버튼을 보여 주고, 그 버튼은 확인 대화상자를 거쳐 응답의 적발 수로 다시 보낸다. 문장을 다시 고치면 목록을 지운다 |

## 알려진 한계

- 신구조문 근거(oldnew) 본문에는 구조문과 신조문이 함께 있어, 구 비율을 새 비율이라고 쓴 문장은 2단을 통과한다. 문장이 구 값을 정당하게 언급하는 경우와 가를 수 없어 이번 범위에서 다루지 않는다.
- `50~80%` 같은 범위 표기에서 앞 숫자는 비율로 읽지 않는다(놓칠 수는 있어도 잘못 잡지는 않는다).
- 실행 이력은 초안 버전을 구분하지 않고 모든 버전의 적발을 보여 준다.

## 오류 상황

- 422를 받은 뒤 관리자가 크리틱을 다시 돌려 적발 수가 바뀌면 다시 보낸 요청도 422를 받는다(새 목록이 온다). 다른 사용자가 먼저 결정하면 다시 보낸 요청은 409 `REVIEW_ALREADY_DECIDED`를 받는다.
