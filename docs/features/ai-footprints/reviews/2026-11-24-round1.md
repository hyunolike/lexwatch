# EGM 검토 1차 (2026-11-24)

- 대상: [spec.md](../spec.md), [design.md](../design.md) 초안
- 검토자: Goldfish 두 명. 설계 비평(egm-design)과 구현 준비도(egm-implementation-readiness)다. 새 문맥으로 실행했고 부모 대화는 넘기지 않았다.
- 두 검토가 같은 지적을 낸 경우가 많아 하나로 묶었다.

## 지적과 조치

| # | 심각도 | 지적(출처) | 조치 |
|---|---|---|---|
| 1 | 높음 | "Attempt가 가장 큰 기록"은 실제와 반대다. 자동 재시도는 같은 행의 Attempt를 올리고, 관리자 다시 실행은 Attempt 0인 새 행을 만든다. 실패한 옛 행이 뽑힌다(설계, 준비도) | 반영. 시작 시각(없으면 예정 시각) 기준으로 고른다. 시도 횟수는 정의가 모호하고 띠에서 쓰지 않아 응답에서 뺐다 |
| 2 | 높음 | 사람 단계를 승인 기록에서 추론하면, 파트너 대기와 돌려보냄이 "완료"로 잘못 보인다(설계, 준비도) | 반영. 상태는 그룹 검토 상태로 정하고 승인 기록은 detail에만 둔다 |
| 3 | 높음 | 검사 단계의 적발 수(단계 출력, 원 초안 기준)와 화면 초안의 적발(수정본 재검사)이 어긋난다(설계, 준비도) | 반영. 최신 초안의 적발을 tier별로 세고, 수정본이면 "수정본 다시 검사"를 적는다 |
| 4 | 높음 | 대체 구현(fallback, 키워드 색인)을 AI로 표시한다. 공개 의무를 다루는 기능에서 생기면 안 되는 오표시다(설계, 준비도) | 반영. AF-06. 공급자가 fallback이거나 임베딩이 없으면 담당을 규칙으로 바꾸고, 라벨도 붙이지 않는다 |
| 5 | 높음 | 근거 부족이나 실패 뒤의 단계가 영원히 "대기"로 보인다. 적발이 있어도 "완료"가 중립 색이다(설계, 준비도) | 반영. `not_run` 상태를 두고, 적발이 있으면 경고 색과 "적발 N건"으로 보인다 |
| 6 | 높음 | 8단계 띠를 머리 아래에 펼쳐 두면 375px에서 약 500px로 확인 안내와 초안을 밀어낸다(설계) | 반영. 확인 안내 아래에 두고, 기본은 칩 한 줄, 요약은 펼침으로 옮겼다. 375px에서 네 줄이다 |
| 7 | 중간 | 함수 입력에 그룹 검토가 없고, 도구 호출 수는 순환 의존이며, 조회 조건에 RunId가 빠졌다(준비도) | 반영. `Build(review, steps, approvals, latestDraft, findingTiers)`로 고정하고 RunId 조건을 적었다. 도구 호출 수는 출력에 있어 별도 조회를 없앴다 |
| 8 | 중간 | 라벨 위치 네 곳 중 관련성 점수는 상세 화면에 없고, 목록 행은 전체가 링크라 버튼을 넣을 수 없다. "초안 제목"이 모호하다(설계, 준비도) | 반영. 관련성 라벨은 범위에서 빼고(띠의 분류 칸으로 대신), 나머지 세 곳을 코드 위치로 적었다 |
| 9 | 중간 | 보이는 글과 접근 이름이 다르다(WCAG 2.5.3). 같은 이름의 버튼이 여러 개다(설계) | 반영. 접근 이름은 "보이는 글, 맥락, 설명 보기"다. 라벨은 h2 밖 형제 요소다 |
| 10 | 중간 | analyze 출력의 하이브리드인데 벡터를 못 쓴 경우, 재현 출력의 retrieval 없음, 신구조문 absent와 error를 다루지 않는다(준비도) | 반영. `denseUsed`가 false면 "키워드 검색", 값이 없으면 문구를 생략한다. 신구조문 세 값을 모두 문장으로 바꾼다 |
| 11 | 낮음 | 쓰지 않는 필드(시도 횟수, 소요 시간, 시각)와 classify 출력 해석이 과하다(설계) | 반영. 응답에서 뺐고, 관련성은 그룹 검토 값을 쓴다 |
| 12 | 낮음 | 진행 중 상태가 화면에서 갱신되지 않는다(설계) | 반영. 진행 중이면 펼침에 새로고침 안내를 둔다. 자동 갱신은 범위 밖으로 한계에 적었다 |
| 13 | 낮음 | 검증 계획에 빠진 경우와 TS 타입 계약(준비도) | 반영. 단위 테스트에 다시 실행, 대체 구현, 재현, 멈춤, 상태별 사람 단계, 수정본을 넣었다. `TrailStage` 타입을 `lib/api.ts`에 두고 백엔드 단계 키와 화면 이름을 Vitest로 대조한다 |

## 남은 쟁점

없다. 재검토는 구현 뒤 코드 리뷰로 대신한다.
