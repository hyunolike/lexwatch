# 명세: 무료 모델 한도 소진 시 자동 교체 (2026-11-20)

- 작성: hh.jang
- 관련: [Cloudflare 공급자 명세](../cloudflare-ai/spec.md)

## 해결할 문제

2026-11-20에 Cloudflare 무료 한도(하루 10,000 Neurons)를 다 써서, 공개 데모도 UTC 자정까지 모든 AI 호출이 429를 받았다. 분류와 분석이 재시도 대기로 멈췄다. 한도가 끝나면 다른 무료 모델로 자동으로 넘어가야 한다.

## 공급자 선택 (조사 2026-11-20)

| 후보 | 결정 | 이유 |
|---|---|---|
| Groq | 채택 | Cloudflare와 같은 `gpt-oss-120b`라 판정 성향이 비슷하다. 무료 등급(약 1,000회, 20만 토큰/일로 알려짐), 입력과 출력을 학습에 쓰지 않는다고 알려져 있고 보관 끄기(ZDR) 설정이 있다. OpenAI 호환 |
| OpenRouter 무료 모델 | 보류 | 50회/일, 무료 모델 목록이 자주 바뀌고 처리 업체마다 데이터 정책이 다르다 |
| Gemini 무료 등급 | 제외 | 무료 사용분은 Google이 학습에 쓰고 사람이 열람할 수 있다고 약관에 있다. 검토 보조 채팅의 변호사 질문이 나갈 수 있다 |

한도는 2026-11-22 Groq 응답 헤더로 확인했다: `openai/gpt-oss-120b` 무료 등급 하루 1,000회, 분당 8,000 토큰. 분당 한도는 1분 안에 풀리므로 Groq는 429의 `Retry-After`를 30초까지 기다렸다 다시 부른다(크리틱 한 번이 약 3,000~5,000 토큰이라 분당 1~2회).

## 요구사항

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FO-01 | 한도나 장애가 나면 다음 공급자로 넘긴다 | 순서 NVIDIA → Cloudflare → Groq(값이 있는 것만). 앞 공급자가 한도 초과(429), 서버 오류, 연결 실패, 시간 초과로 실패하면 같은 요청을 다음 공급자로 보낸다. 출력 형식 오류는 넘기지 않는다(모델 답의 문제라 호출부가 다룬다) |
| FO-02 | 다 쓴 공급자를 다시 두드리지 않는다 | 한 요청 안에서 한도 초과를 받은 공급자는 그 요청의 나머지 호출(에이전트의 여러 턴)에서 건너뛴다. 같은 서버 인스턴스는 그 공급자를 5분(또는 `Retry-After`가 더 길면 그만큼) 건너뛴다 |
| FO-03 | 출처를 사실대로 표시한다 | 실제로 답한 공급자가 출처다. Groq가 답하면 출처 종류 `groq`, 화면 라벨 "Groq". 다른 공급자로 표시하지 않는다 |
| FO-04 | 공급자마다 같은 시간 예산을 지킨다 | 넘겨도 요청 전체 시간 예산(분류 50초, 크리틱 120초, 분석 120초)은 하나다. 남은 시간이 없으면 넘기지 않고 마지막 오류를 낸다 |
| FO-05 | 모두 실패하면 지금처럼 | 마지막 오류를 그대로 낸다. 백엔드는 지금처럼 재시도하고, 한도 초과면 `Retry-After`를 따른다 |
| FO-06 | 분류의 추론 강도 낮추기(CF-06)는 gpt-oss 공급자 모두에 적용 | Cloudflare와 Groq 모두 분류에서 `reasoning_effort=low` |

## 검증

- Python: 순서와 넘김 조건, 형식 오류는 넘기지 않음, 한 요청 안에서 건너뛰기, 인스턴스 쿨다운, 시간 예산, 출처, 환경변수별 선택
- .NET과 웹: 출처 종류 `groq` 매핑, 저장 허용, 라벨과 색 대비
- 실호출(2026-11-22): Groq 직접 호출 1.2초. Cloudflare를 한도 초과로 흉내 낸 묶음에서 같은 요청을 Groq가 0.5초에 답함.
- 크리틱 평가(같은 20건, Groq): 규칙 있음 적발 12/13, 규칙 ID 정확 10/13, 거짓 양성 0. 규칙 없음 적발 13/13, 거짓 양성 1건. Cloudflare(같은 모델)의 두 실행 13/13·13/13, 13/13·9/13과 같은 범위의 편차다. 분당 한도 때문에 40회에 7분 14초
