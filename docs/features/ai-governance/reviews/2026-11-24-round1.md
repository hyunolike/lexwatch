# EGM 검토 1차 (2026-11-24)

- 대상: [spec.md](../spec.md), [design.md](../design.md) 초안
- 검토자: Goldfish 두 명. 설계 비평(egm-design), 구현 준비도(egm-implementation-readiness). 새 문맥으로 실행했고 부모 대화는 넘기지 않았다.

## 설계 비평 (10건)

| # | 심각도 | 지적 | 조치 |
|---|---|---|---|
| 1 | 높음 | 워크플로 단계(CriticSteps, CritiqueStep, SetGroupStatusAsync)가 그룹 상태를 조건 없이 덮어쓴다. 1·2단 적발 직후 3단이 돌 때 승인하면 결정이 사라진다(기존 Approved에도 있는 구멍) | 반영. GV-13: 그룹의 활성 단계가 남아 있으면 모든 결정이 409 `ANALYSIS_IN_PROGRESS` |
| 2 | 중간 | 수정 없는 승인은 재검사 적발을 버려 파트너가 무엇을 확인했는지 볼 수 없다 | 반영. 승인 기록에 `findings_json`을 고정하고 상세 응답 `lawyerApproval.findings`로 보인다 |
| 3 | 중간 | 돌려보낸 뒤 변호사가 문장을 지워 적발 0건으로 만들면 파트너를 거치지 않고 나간다 | 반영. 돌려보낸 기록이 있으면 다음 승인은 항상 `AwaitingPartner` |
| 4 | 중간 | "ActorRole 비교 한 곳" 문구가 실제 설계와 다르다 | 반영. "역할 검사만 하며 같은 사람 검사는 없다"로 고침. 신원 열은 SSO 없이는 쓸 값이 없어 두지 않았다 |
| 5 | 중간 | 역할 필터가 `/api`와 `/api/runs` 두 곳에 있다 | 반영. 공통 역할 집합, 거버넌스는 별도 그룹(admin) |
| 6 | 중간 | 기록 턴을 2000자로 먼저 자르면 경계의 번호 앞부분이 샌다. 자리표시가 원문보다 길 수 있다 | 반영. 원문 전체 가리기 → 한도로 자르기(자리표시 중간 끊지 않음) |
| 7 | 중간 | NotifyStep 본문이 변호사 승인만 적는다 | 반영. GV-14 |
| 8 | 낮음 | 기록의 FK와 보존 정책이 없다 | 반영. FK 없음, 90일 정리, jsonb |
| 9 | 낮음 | 공백 구분 주민등록번호와 전화번호를 놓친다 | 반영. 두 규칙에 공백 구분 추가 |
| 10 | 낮음 | 키 없는 고정 응답이 거절로 집계된다. 질문과 기록을 이중 집계한다 | 반영. `unavailable` 결과, 질문분만 집계. 거절 사유 기록은 AI 계약 변경이 필요해 알려진 한계로 둠 |

## 구현 준비도 (10건)

| # | 심각도 | 지적 | 조치 |
|---|---|---|---|
| 1 | 높음 | 카드 규칙이 `2026-11-24 2026-12-31`을 16자리로 읽고 Luhn까지 통과한다 | 반영. 실제 묶음 형식만 받는 패턴, 오탐 테스트 추가(통과) |
| 2 | 중간 | 계좌 규칙의 날짜 제외 판정식이 모호하다 | 반영. "날짜로 시작하면 제외" 판정식 명시, 테스트 추가 |
| 3 | 중간 | 가리기와 자르기 순서 | 설계 6번과 같이 반영 |
| 4 | 중간 | 오류 응답일 때 말풍선과 건수 처리 | 반영. GV-04: 이번 질문분만 세고, 오류 때는 말풍선을 바꾸지 않음 |
| 5 | 중간 | 웹 채팅 계약이 빠져 있다 | 반영. `maskedUserTurn`, `maskNotice` |
| 6 | 중간 | RunEndpoints 필터와 웹 `getRole` | 설계 5번과 같이 반영 |
| 7 | 중간 | 결과 매핑, 소요 시간 기준, 7일 정의, 집계 키, 정렬 | 반영. GV-05, GV-06, 설계 4절 |
| 8 | 낮음 | 고객사 규칙이 자리표시를 깨뜨린다. 부분 일치 정책 | 반영. 고객사 먼저, 부분 일치 허용 명시와 테스트 |
| 9 | 낮음 | rrn과 card 겹침 라벨, 날짜 판정 수준, 공백 전화 | 반영. 먼저 도는 규칙이 이김, 월과 일 범위만 봄 |
| 10 | 낮음 | 검사 순서 행렬이 없다 | 반영. 설계 5.2 표 |
