# 명세: LexWatch 디자인 시스템 v2

- 상태: 검토 반영본 v2 (2026-11-25). 변경: DS2-07 폭 기억 삭제, DS2-11 재실행 접수로 축소, DS2-12 다음 범위로, 필수와 선택 구분. [EGM 통합 검토](reviews/consolidated_review_report.md)
- 작성자 결정(2026-11-25): 결정 버튼은 지금처럼 화면 아래 고정(A12). 범위는 검토 권고대로 줄인다(A13)
- 작성: hh.jang
- 근거 자료: [research.md](research.md), v1 [명세](../design-system/spec.md)와 [설계](../design-system/design.md)
- 작성자 결정(2026-11-24): 방향은 법률 AI 전문 도구의 절제된 편집 디자인(Harvey, Legora 계열). 마스코트 렉스는 줄여서 유지. 다크 모드를 넣는다. 필요한 패턴, 라이브러리, 에셋은 직접 도입한다.

## 1. 해결할 문제

v1은 토큰, 한국어 라벨, 출처 색과 상태 색 분리, 대비 테스트를 갖췄다. 2026-11-24 역할별 사용 평가에서 남은 문제는 "도구로서의 무게"다.

1. **검토 화면이 근거 대조에 맞지 않는다.** 초안을 읽다가 인용 칩을 눌러 팝오버를 열고, 신구조문은 화면 아래로 내려가 본다. 변호사는 문장과 근거를 나란히 놓고 봐야 하는데 위아래를 오간다.
2. **누가 썼나와 맞나가 한눈에 구분되지 않는다.** 출처 라벨(AI, 규칙, 사람)과 크리틱 결과(확인 필요)가 같은 모양의 작은 배지로 섞인다. 평가에서 "확인 필요 0"인 초안에도 법적 오류가 있었으므로, "검사를 통과했다"와 "맞다"를 화면이 혼동하게 두면 안 된다.
3. **반복 작업이 마우스 위주다.** 대기함을 훑고, 다음 지적으로 가고, 승인하는 일을 매일 한다. 단축키와 검색이 없다.
4. **밝은 화면만 있다.** 오래 읽는 사용자에게 시스템 다크 설정을 따르지 않는다.
5. **인상이 소비자 앱에 가깝다.** 3D 마스코트가 헤더와 빈 화면에 크게 나오고, 제목과 본문이 같은 서체라 문서의 위계가 약하다.
6. **결과 알림이 한 가지뿐이다.** 재실행 접수처럼 화면에 바로 보이지 않는 결과도 화면 위 안내 상자로만 알린다.

## 2. 사용자

v1 명세 2절과 같다. 변호사, 파트너, 패러리걸과 지식관리 담당, 관리자. 업무용 데스크톱이 주 환경이고 긴 법령 문장을 오래 읽는다.

## 3. 범위

포함:
- 두 테마(밝게, 어둡게)의 의미 토큰과 시스템 설정 따르기, 수동 전환
- 제목용 세리프(Noto Serif KR), 읽기 글자 17px
- 부품 변형 관리(cva, tailwind-merge)
- 새 패턴: 검토 상세 분할 화면, 인용 미리보기, 문장별 검증 상태, 키보드 단축키, 명령 팔레트, 토스트(재실행 접수), 스켈레톤
- 출처 라벨을 "누가 만들었나" 네 종류(AI, 규칙, 사람, 재현)로 정리
- 렉스 축소(헤더 로고는 평면 마크로, 렉스는 빈 화면과 서버 깨우기 대기에만)
- 일곱 화면과 `/design-system` 적용, README 스크린샷 갱신

하지 않을 것:
- 백엔드와 AI 서비스 변경. 화면에 필요한 데이터는 지금 API에 있다.
- 새 마스코트 그림 생성. 기존 WebP를 크기만 줄여 쓴다.
- 본문 세리프 기본값. `/design-system`에서 비교만 하게 둔다(research 2.2).
- 행 단위 "내가 확인함", 실행 타임라인 읽은 범위 표시(research P9, P10). 다음 범위.
- 휴대폰 전용 서랍, 레이아웃 애니메이션 라이브러리(motion).
- 표 밀도 전환(옛 DS2-12). 대기함은 표가 아니라 링크 격자라 효과가 작다. 다음 범위.
- 분할 화면 폭 기억. 새로 열면 기본 비율로 돌아간다.
- 재실행 접수 밖의 토스트(테마 변경, 링크 복사). 테마는 화면이 바로 바뀌어 알릴 것이 없고, 링크 복사 기능은 지금 없다.

## 4. 요구사항

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| DS2-01 | 두 테마를 지원한다 | `:root`(밝게)와 어둡게 값이 모두 있다. 저장된 선택이 없으면 `prefers-color-scheme`을 따른다. 명령 팔레트와 헤더 메뉴에서 시스템, 밝게, 어둡게를 고르고 브라우저에 저장한다. 새로 고침해도 첫 그림이 잘못된 테마로 깜박이지 않는다 |
| DS2-02 | 두 테마 모두 대비 기준을 지킨다 | 대비 테스트가 두 테마의 모든 쌍을 검사한다. 글자 4.5:1, 경계와 포커스 링 3:1. 포커스 링은 항상 2px 띄워 링 옆이 바탕이 되게 한다 |
| DS2-03 | 화면 코드는 테마를 모른다 | 화면과 부품에 `dark:` 변형이나 16진수 색이 없다. 색은 의미 토큰 클래스로만 쓴다. 검사 스크립트가 빌드 CSS에서 두 테마 값을 확인한다 |
| DS2-04 | 문서 위계를 서체로 보인다 | 페이지 제목과 검토 상세의 법령명은 Noto Serif KR(자체 호스팅, 가변 글꼴, 조각 로딩). 읽는 글(초안 문장, 조문, 알림 본문, 채팅 답)은 17px, 줄높이 30px, 한 줄 최대 40em. 글꼴을 못 받아도 배치가 깨지지 않는다 |
| DS2-05 | 출처 라벨은 누가 만들었나를 말한다 | AI(보라), 규칙(청록), 사람(자주), 재현(회색 점선) 네 색. AI 라벨 글자에 공급자(Cloudflare, Groq, NVIDIA)를 적는다. 출처 색은 상태 색 계열을 쓰지 않는다(v1 DS-03 판정 규칙 유지) |
| DS2-06 | 검증 상태는 출처와 다른 모양이다 | 초안 문장마다 왼쪽 여백에 "검사 통과", "확인 필요"를 아이콘과 글자로 보인다. 출처 라벨과 다른 부품(`CheckMark`)이다. 상단 요약은 "자동 검사 통과는 내용이 맞다는 뜻이 아니에요"를 함께 적는다 |
| DS2-07 | 검토 상세는 초안과 근거를 나란히 본다 | 1280px 이상에서 왼쪽은 초안(읽기 폭), 오른쪽은 근거 패널(인용 목록, 선택한 근거의 앞부분, 연결된 신구조문). 문장을 고르거나 인용 칩을 누르면 오른쪽이 그 근거로 바뀌고 강조한다. 1280px 미만에서는 같은 근거 패널이 초안 아래에 온다. 패널 폭은 끌어서 바꾸고 키보드로도 바꾼다(분리선에 `role="separator"`, 화살표 키). 폭은 저장하지 않는다. 결정 버튼은 지금처럼 화면 아래 고정 상자에 둔다 |
| DS2-08 | 인용을 마우스 올림으로 미리 본다 | 인용 칩에 마우스를 올리면 근거 제목, 앞부분 240자, 원문 링크 카드가 뜬다. 키보드는 칩에 포커스한 뒤 Enter로 연다. 클릭과 Enter는 고정해서 연다(분할 화면에서는 오른쪽 패널로 이동). Esc로 닫히고 포커스가 칩으로 돌아온다 |
| DS2-09 | 키보드로 반복 작업을 한다 | 대기함: `j`/`k` 다음/이전 행, `Enter` 열기. 검토 상세: `]`/`[` 다음/이전 확인 필요 문장, `a` 승인, `e` 수정, `r` 반려. 모든 화면: `?` 단축키 도움말, `⌘K`/`Ctrl+K` 명령 팔레트. 입력창에 포커스가 있거나 한글 조합 중이면 무시한다. `a`는 바로 승인하지 않고 지금의 확인 대화상자를 연다. 역할상 할 수 없는 동작의 단축키는 아무 일도 하지 않는다 |
| DS2-10 | 명령 팔레트로 이동하고 설정한다 | 화면 이동, 대기함의 검토 검색(법령명), 역할 전환, 테마 전환. 한글을 입력하는 동안 Enter가 항목을 실행하지 않는다. 결과가 없으면 "찾는 항목이 없어요" |
| DS2-11 | 재실행 접수 결과는 토스트로 알린다 | 실행 타임라인에서 재실행을 누른 결과(접수됨, 다시 할 것 없음)는 토스트(5초, 최대 3개, 화면 읽기 프로그램이 읽음)로 알린다. 권한 없음, 실패, 서버 깨우는 중처럼 사용자가 고쳐야 하거나 기다려야 하는 결과와 승인, 반려의 실패는 지금처럼 화면 위 안내 상자로 남긴다 |
| DS2-12 | (다음 범위) | 표 밀도 전환. 3절 하지 않을 것 |
| DS2-13 | 서버가 깨어 있는 로딩은 스켈레톤으로 보인다 | 대기함, 검토 상세, 법안 레이더, 운영 현황이 실제 배치와 같은 회색 막대를 보인다. 서버가 잠든 첫 요청은 지금의 렉스 대기 화면이 맡는다. 움직임 줄이기 설정에서는 반짝이지 않는다 |
| DS2-14 | 렉스는 여유 있는 순간에만 작게 나온다 | 헤더는 평면 로고 마크(SVG, 테마에 맞는 색). 렉스는 빈 화면(최대 120px)과 서버 깨우기 대기 화면에만. v1 DS-15의 금지 위치는 그대로 |
| DS2-15 | 부품 변형은 한 표에서 관리한다 | Button, Badge, StatusLozenge, SourceLabel, Callout이 cva 변형 표를 쓴다. 클래스 합치기는 `tailwind-merge` 확장 설정을 거치며, 사용자 정의 글자 크기 토큰(`text-ui` 등)이 색 클래스와 함께 있어도 사라지지 않는다(단위 테스트) |
| DS2-16 | 디자인 시스템 화면이 v2를 보여 준다 | `/design-system`에 두 테마의 견본과 대비 값, 글자 척도(세리프 제목 포함), 읽기 글꼴 비교(산세리프와 세리프), 새 부품 예시가 있다 |

### 4.1 필수와 선택

필수: DS2-01~08, DS2-14, DS2-15(Button, 배지, Callout), DS2-16의 두 테마 견본. 선택(마감이 밀리면 이 순서로 줄인다): DS2-10의 검토 검색 → DS2-07의 폭 끌기(고정 비율 58:42로 대신하고 DS2-07 수용 기준에서 "끌어서 바꾸고" 삭제) → DS2-13은 대기함과 검토 상세만 → DS2-16의 읽기 글꼴 비교 칸. DS2-09와 DS2-11은 필수 다음 차례로 구현한다.

## 5. 오류와 예외 상황

- 저장된 테마 값이 알 수 없는 값이거나 저장소를 쓸 수 없으면(사생활 보호 모드) 시스템 설정을 따른다.
- 세리프 글꼴을 못 받으면 대체 명조(AppleMyungjo, Batang)나 산세리프로 보이고 줄바꿈이 크게 달라지지 않는다.
- 인용 ID에 해당하는 근거가 없으면 미리보기와 근거 패널에 "근거를 찾을 수 없어요"를 보인다(v1과 같음).
- 분할 화면에서 신구조문이 없는 근거(현행 조문만)를 고르면 본문만 보인다.
- 명령 팔레트의 검토 검색은 대기함을 한 번 받은 결과만 쓴다. 서버가 잠들어 있으면 이동과 설정 항목만 보인다.
- 단축키가 브라우저나 화면 읽기 프로그램의 단축키와 겹치지 않게 수정자 없는 글자 키는 본문에 포커스가 있을 때만 받는다.

## 6. 성공 판단

- 대비 테스트(두 테마), `tailwind-merge` 설정 테스트, 단축키와 테마 계산의 단위 테스트가 통과한다.
- 기존 웹 테스트, 타입 검사, 린트, 빌드가 통과한다.
- 운영 데모에서 일곱 화면을 두 테마, 1440px과 390px으로 확인하고 스크린샷을 남긴다.
