# Stage 6: Comprehension 보고서

- 대상: `docs/features/design-system-v2/design.md` (초안 v1, 2026-11-24). FeatureRange 1–83(1–2절), DetailedRange 84–173(3–5절)
- 검토자: egm-comprehension (새 문맥, 대상 문서만 읽음, 2026-11-25)

## What this proposes

이 문서는 LexWatch 웹 화면의 디자인 시스템을 v1에서 v2로 올리는 설계다. 핵심은 다섯 가지다.

1. 의미 토큰 이름(`canvas`, `ink`, `brand` 등)은 그대로 두고 값만 밝은 테마와 어두운 테마로 나눈다. Tailwind `@theme inline`이 CSS 변수(`--lw-*`)를 가리키게 하고, 테마는 `<html data-theme>`와 `prefers-color-scheme`으로 바꾼다. 그러면 화면 코드는 지금 어느 테마인지 몰라도 된다.
2. 출처 색을 공급사별 다섯 색에서 "누가 만들었나" 기준의 네 색(AI, 규칙, 사람, 재현)으로 줄인다.
3. 새 부품을 들인다. cva와 tailwind-merge 기반 `cn`, 직접 작성한 테마 스크립트, 단축키, 명령 팔레트, 토스트, 밀도, 스켈레톤, 평면 로고 마크, 문장별 검증 표시가 있다.
4. 검토 상세 화면은 1280px 이상에서 왼쪽 문장, 오른쪽 근거 패널로 나눈다. 결정 버튼은 헤더 줄로 올린다.
5. 작업은 6단계로 진행하며, 단계마다 테스트, 타입 검사, lint, 빌드 명령이 통과해야 한다.

## How the existing system works, per this document

지금(v1)은 Tailwind `@theme`에 밝은 테마 하나만 있다. 색은 고정 16진수 값이고 `html { color-scheme: light }`로 정해져 있다. 빌드 검사 스크립트가 이 두 가지를 요구하고, `design/tokens.ts`의 `parseColorTokens`가 토큰을 읽어 대비 테스트를 돌린다.

AI 출처 색은 공급사별 `source-*` 토큰 다섯 쌍으로 칠한다. 클래스 합치기는 `lib/cx.ts`가 맡고, 부품은 Base UI(`@base-ui/react`) 위에 있다.

검토 상세 화면은 한 칸 구성이다. 결정 버튼(반려, 수정, 승인)은 화면 아래 고정 상자에 있고, 인용 칩을 누르면 팝오버가 뜬다. 헤더에는 "렉스"가 들어 있다.

## 총평

1–2절의 방향(테마 변수, 출처 네 종류, 라이브러리 선택)은 문서만으로 따라갈 수 있다. 3–5절은 파일 목록은 있지만 프로젝트 고유 개념(렉스, 역할, 출처 판별, 검증 상태, 밀도)과 단축키, 칩 동작의 규칙이 빠져 이 문서만으로는 구현하거나 검증할 수 없다. Blocker 없음, Major 10, Nit 6.
