# LexWatch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공포된 법령 개정을 매일 수집해 실무그룹별로 분류하고, Nemotron 에이전트가 근거를 인용한 영향 메모 초안을 쓰고, 크리틱 3단을 거쳐 변호사가 승인하면 알림이 나가는 Workflow 서비스를 11/24까지 배포한다.

**Architecture:** .NET API가 Workflow 엔진(DB 기반 단계 큐, `SKIP LOCKED`), 수집, 크리틱 1·2단, 승인을 맡고 Render 무료에 상시 떠 있다. 상태 없는 Python FastAPI가 Vercel에서 분류·영향 분석 에이전트·크리틱 3단·검토 보조를 맡고 NVIDIA NIM(Nemotron, NeMo Retriever)을 부른다. Next.js 화면이 Vercel에서 승인 대기함, 초안 상세, 실행 이력을 보여 준다.

**Tech Stack:** .NET 10, ASP.NET Core Minimal API, EF Core + Npgsql + Pgvector.EntityFrameworkCore, Microsoft.Extensions.Resilience, NSwag, xUnit + Testcontainers.PostgreSql / Python 3.12, FastAPI, Pydantic v2, httpx, NeMo Guardrails, pytest, uv / Next.js 16, TypeScript, Tailwind, pnpm / Supabase Postgres(pgvector) / Render, Vercel, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-16-lexwatch-design.md`

## Global Constraints

- 데이터는 국가법령정보센터 Open API의 공포 법령만. 입법예고, 가상 사건·의뢰인 데이터는 넣지 않는다.
- 초안은 이 실행의 근거 저장소(`evidence`)에 있는 근거 ID로만 인용한다.
- 정직성: 모든 `step_run`은 `provider_kind`(`nvidia` | `fallback` | `replay` | `none`)를 가진다. 화면 배지는 이 값을 그대로 쓴다(초록·주황·회색 "재현"). 대체 구현을 NVIDIA로 표시하지 않는다.
- 기본 모델: LLM `nvidia/nemotron-3.5-super-vl-120b-a12b`, 임베딩 `nvidia/nemotron-3-embed-1b`, 리랭커 `nvidia/llama-nemotron-rerank-vl-1b-v2`. Task 0 결과로 바뀌면 `docs/notes/2026-11-16-spike.md`에 적고 이 줄을 고친다.
- 분류 신뢰도 기준: `>= 0.7` 진행, `0.4 <= c < 0.7` 진행하되 `needs_review`, `< 0.4` 해당 그룹 `closed_irrelevant`.
- 에이전트 상한: 도구 호출 8회, 전체 120초. 검토 채팅 상한: IP당 하루 10회, 전체 하루 200회.
- 데모 초기화 매일 04:00 KST(`0 19 * * *` UTC), 수집 매일 07:00 KST(`0 22 * * *` UTC).
- 화면 문구에 "변호사 대체", "실시간"을 쓰지 않는다. 화면 상단 고정 문구: "데모 데이터는 매일 새벽 초기화됩니다."
- 비밀값은 환경 변수로만. `.env.example`만 커밋한다. 저장소는 공개.
- 커밋 메시지는 `feat:`/`fix:`/`docs:`/`chore:` + 한국어 요약.

## Review Focus

1. **Render가 잠든 동안 `running`으로 멈춘 단계** — 깨어난 뒤 리스(lease) 5분이 지난 단계는 다시 집혀야 한다. Task 2가 테스트한다.
2. **같은 날 수집이 두 번(또는 동시에) 들어옴** — 같은 개정으로 실행이 둘 생기면 안 된다. Task 3이 테스트한다.
3. **법령 API가 200으로 빈 결과나 오류 본문을 줌** — 빈 목록(정상)과 오류 응답(재시도 대상)을 구분해야 한다. Task 3이 테스트한다.
4. **LLM이 형식은 맞는데 비어 있는 인용(`citations: []`)이나 근거 저장소에 없는 ID를 냄** — Python 스키마가 빈 인용을 422로 막고, .NET 크리틱 1단이 없는 ID를 표시한다. Task 5·Task 9가 테스트한다.
5. **두 평가자가 같은 초안을 동시에 승인·반려** — 결정은 한 번만 기록되고 나중 요청은 409. Task 10이 테스트한다.
